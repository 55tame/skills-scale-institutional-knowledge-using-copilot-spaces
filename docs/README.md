# OctoAcme Project Management Docs

A landing page for the project-management guidance in the [`docs/`](./) folder. These documents describe how OctoAcme initiates, plans, delivers, releases, and improves work across project lifecycles.

## Project management process summary

OctoAcme manages work through a lightweight lifecycle:

1. **Initiation:** Validate the business need, define measurable outcomes, identify stakeholders, capture initial risks and dependencies, and decide whether to proceed.
2. **Planning:** Turn approved work into a prioritized, estimated backlog; agree on acceptance criteria and a Definition of Done; identify dependencies, risks, milestones, and a release plan.
3. **Execution and tracking:** Deliver in small increments using a project board, regular team and stakeholder communication, reviews and demos, automated testing, and ongoing progress and risk tracking. Escalate blockers through the defined team, PM, product lead, and sponsor paths.
4. **Release and deployment:** Confirm acceptance criteria, CI and security checks, release notes, smoke tests, and rollback plans; deploy and verify, then communicate the release.
5. **Retrospective and continuous improvement:** Review learnings after sprints, releases, milestones, and incidents; choose a small number of owned action items and track their impact.

Across the lifecycle, the Project Manager coordinates delivery, risks, schedules, and communications; the Product Manager owns outcomes and priorities; developers build and test; QA validates quality; and stakeholders provide input and approvals. Teams use clear ownership, data-informed decisions, iterative delivery, and psychological safety.

## How to use this documentation

- Start with the overview for the high-level lifecycle and principles.
- Use the initiation and planning guides to validate, scope, and prepare work.
- Reference the execution, risk, and release guides during delivery.
- Close the loop with retrospectives and improvements so the team learns continuously.
